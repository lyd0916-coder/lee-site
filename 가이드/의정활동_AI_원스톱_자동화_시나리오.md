## 1. 한눈에 보는 전체 흐름

```
[현장] 간담회·현장방문·포럼·민원 상담
   │  (녹음 / 메모 / 사진)
   ▼
① 기록 정리 ── 녹취를 글로 바꾸고 요약
   ▼
② 분류 ─────── 민원 / 정책 방향 / 조례 / 예산 / 후속 확인
   ▼
③ 후속 업무 ── 민원 처리 요청서, 정책 메모, 조례 검토 메모
   ▼
④ 블로그 글 ── 주민이 읽기 쉬운 글 (네이버 블로그용)
   ▼
⑤ 쇼츠 대본 ── 40~60초, 시간표(화면·자막·내레이션)
   ▼
⑥ 영상 설계 ── 모션그래픽 "촬영 지시서" 프롬프트
   ▼
⑦ 영상 생성 ── AI 영상 생성 → 내레이션·음악 → 업로드
```

**핵심 원칙 3가지 (강의에서 배운 것)**

| 원칙 | 강의 내용 | 의정활동 적용 |
|---|---|---|
| ① 프롬프트는 **촬영 지시서**처럼 | 길이, 샷 구성, 초 단위 타이밍, 색·글꼴, 카메라, 사운드, 금지사항까지 적는다 | 쇼츠 대본을 "몇 초에 무슨 화면·무슨 자막"으로 쪼갠다 |
| ② 모르면 **AI·레퍼런스에게 맡긴다** | 가이드 프롬프트 + 리서치 요청 / 마음에 드는 영상을 분석시켜 프롬프트로 변환 | 잘 만든 지자체·의원 쇼츠를 레퍼런스로 분석시킨다 |
| ③ 모양이 중요한 건 **이미지로 고정** | 캐릭터·제품은 레퍼런스 이미지를 프롬프트 단계와 영상 생성 단계 **두 번** 넣는다 | 의원 캐릭터, 의회 로고, 현장 사진, 시설 사진을 고정 자료로 쓴다 |

## 2. 강의 핵심 정리 (단락별)

### 2-1. 왜 지금 가능해졌나
- 예전 AI 영상은 "실사"는 잘했지만, **글자·도형·그래픽 움직임(2D 모션그래픽)**은 약했다.
- 최근 모델은 디자인 요소가 중요한 모션그래픽도 쓸 만한 품질로 만든다.
- 강의는 세 가지를 직접 만든다: **① 키네틱 타이포그래피 ② 캐릭터 애니메이션 ③ 제품 프로모션 모션그래픽**.

### 2-2. 키네틱 타이포그래피란
- **글자 자체가 움직이면서 메시지를 전달**하는 방식. 커지고, 작아지고, 이동·회전·변형하면서 그 움직임이 메시지를 강조한다.
- 가장 먼저 해 보는 이유: 캐릭터·제품처럼 **모양을 장면마다 똑같이 유지할 필요가 없어서** AI 테스트가 쉽다.
- 의정활동에서는 **"한 문장 메시지"** 전달에 딱 맞다. (예: "선생님이 임신하면, 왜 축하보다 걱정이 먼저일까요?")

### 2-3. 방법 1 — 가이드 프롬프트로 처음부터 설계
1. 가이드 프롬프트(작성 규칙서)를 ChatGPT·Gemini·Claude에 먼저 넣는다.
2. "가이드에 따라 ○○를 리서치하고 키네틱 타이포그래피 영상 생성 프롬프트를 써 줘"라고 요청한다.
3. AI가 만들어 주는 프롬프트 구성 (= 촬영 지시서):

| 항목 | 내용 예시 (강의 10초 영상) |
|---|---|
| 길이·형식 | 10초, 키네틱 타이포 + 에디토리얼 그래픽 + UI 모션, 멀티샷 |
| 디자인 방향 | 컬러, 글꼴, 그리드, 그래픽 요소 |
| **샷 구성 (핵심)** | 5개 샷. 샷1(0~1.6초) 질문으로 시선 잡기 → 샷2 키워드가 이미지·UI로 연결 → 샷3(3.7초~) 핵심 메시지와 연결선 → 샷4 다루는 분야 빠르게 나열, 키워드마다 다른 등장·전환 → 샷5(8.3초~) 채널명 완성 후 정지 |
| 필수 문구 목록 | 화면에 나올 문구는 **큰따옴표 안**에, 띄어쓰기·문장부호까지 정확히. 문구를 바꾸면 **필수 문구 목록도 같이** 바꾼다 |
| 카메라 공통 규칙 | "선택 → 변형 → 정렬 → 출력" 같은 하나의 흐름으로 통일, 과한 흔들림 금지 |
| 사운드 | 클릭·전환 효과음, 120BPM 배경음악 |
| 가드레일(금지사항) | 불필요한 요소, 엉뚱한 글자, 로고 왜곡 등을 막아 일관성 유지 |

4. 같은 구성에 **스타일만 바꾸면**(예: 네오브루탈리즘 에디토리얼) 전혀 다른 느낌의 영상이 나온다. → 같은 대본으로 여러 버전 테스트 가능.

### 2-4. 영상 생성 설정 (강의 기준)
- 강의는 노드(블록)를 연결하는 캔버스형 AI 영상 플랫폼을 사용. 여러 영상 모델을 쓸 수 있는 다른 서비스도 무방.
- 영상 모델: 텍스트·그래픽 표현, 복잡한 지시 반영, 레퍼런스 기반 모션 제어가 강하고 비용 대비 품질이 좋은 범용 모델 사용.
  > ※ 강의 음성에서 서비스·모델 이름이 정확히 들리지 않았습니다(받아쓰기상 "뉴테이크/유테이크", "미니맥스 H3"). 실제 사용 전 정확한 이름과 요금을 확인하세요.
- **길이 = 프롬프트에 설계한 길이**(10초 설계 → 10초 설정, 13초 설계 → 13초 설정)
- **화면 비율**: 일반 유튜브 16:9 / **쇼츠·릴스 9:16**
- 해상도: 용도·비용에 맞게. 생성 시간은 대략 5~10분.

### 2-5. 방법 2 — 마음에 드는 영상을 레퍼런스로
- 핀터레스트 등에서 원하는 느낌의 모션그래픽을 찾는다.
- ChatGPT의 **웹 탐색/컴퓨터 사용(에이전트) 모드**에 링크 + "이 영상을 분석해서 같은 스타일로 만들 수 있게 프롬프트를 써 줘" + 가이드 프롬프트를 함께 넣는다.
- AI가 화면을 캡처하며 **색감, 화면 구성, 글자 움직임, 장면 전환 방식**을 분석 → 가이드 형식의 프롬프트로 정리.
- 전문 용어를 몰라도 **레퍼런스에서 용어와 연출을 뽑아낼 수 있다**는 것이 핵심.
- 플랫폼에 따라 **"스마트 분석"**처럼 영상을 업로드하면 **샷 / 모션 / 음악**을 나눠 분석해 주는 기능도 있다. 분석된 샷들을 영상 생성에 레퍼런스로 직접 연결 + 기존 프롬프트를 함께 넣으면, 말로 설명하기 어려운 복잡한 움직임(글자 복제 트레일 등)도 반영된다.

### 2-6. 캐릭터 애니메이션 — 일관성 유지법
1. 캐릭터 레퍼런스 이미지 준비 (직접 그린 것 또는 이미지 AI로 생성).
2. **레퍼런스 이미지 + 가이드 프롬프트**를 함께 넣고 텍스트 AI에게 "이 캐릭터로 ○○ 주제 모션그래픽 영상 프롬프트를 써 줘"라고 요청.
3. 영상을 생성할 때 **레퍼런스 이미지를 한 번 더** 넣는다. → 캐릭터 모양이 거의 그대로 유지된다.
   - 프롬프트 단계에서만 넣으면 "느낌"만 비슷해지고, 영상 단계에서도 넣어야 "모양"까지 같아진다.

### 2-7. 제품 프로모션 — 형태·로고 고정
- 제품은 형태, 색, 로고, 글자가 장면마다 달라지면 안 된다.
- 프롬프트를 만든 뒤 **제품 이미지를 레퍼런스로 함께 넣고** 영상 생성 → 외형은 유지, 움직임·연출만 다양하게.

### 2-8. 25칸 연속 스토리보드로 미리 보기
- 영상을 만들기 전, **이미지 한 장 안에 25개 연속 장면**을 그리게 해서 흐름(구도·순서·전개)을 먼저 확인.
- 이미지 생성 AI(예: ChatGPT 이미지 생성)로도 충분히 가능 → 유료 영상 크레딧을 아끼는 방법.
- 제품 이미지 한 장만 넣고 스토리보드를 만든 뒤 그걸 바탕으로 영상을 만들면 **스토리가 살아 있는** 영상이 된다.

## 3. 의정활동에 적용하는 7단계 시나리오

> 예시 상황: "오늘 ○○동 학부모들과 통학로 안전 간담회를 했다."

| 단계 | 내가 할 일 (입력) | AI가 해 줄 일 (출력) | 사용 프롬프트 |
|---|---|---|---|
| ① 기록 | 녹음 파일 또는 녹취록, 메모, 사진 목록 | 회의록 형식 요약 (참석자·주요 발언·요청사항·약속한 것) | 4-1 |
| ② 분류 | ①의 요약 | 민원 / 정책 방향 / 조례 / 예산 / 후속확인 표 | 4-2 |
| ③ 후속 업무 | ②의 표 | 민원 처리 요청서, 정책 메모, 조례 검토 메모 초안 | 4-3 |
| ④ 블로그 | ①~③ 결과 + 사진 | 네이버 블로그 글 (제목 3안, 본문, 해시태그) | 4-4 |
| ⑤ 쇼츠 대본 | ④의 블로그 글 + 사진 목록 | 40~60초 시간표 (화면·자막·내레이션), 설명란 | 4-5 |
| ⑥ 영상 설계 | ⑤의 대본 + 4-8 가이드 | 모션그래픽 촬영 지시서 프롬프트 (영문/국문) | 4-6 |
| ⑦ 생성·마무리 | ⑥ 프롬프트 + 레퍼런스 이미지 | 영상 생성 → 내레이션 녹음 → 음악·효과음 → 업로드 | 4-7 |

**시간 감각**: ①~⑥은 AI 대화창 하나에서 30분 이내. ⑦은 영상 생성 대기 포함 1시간 내외.

## 4. 복사용 프롬프트 모음

> 사용법: 회색 상자 안 내용을 **통째로 복사** → AI 질문창에 붙여 넣기 → `[대괄호]` 부분만 바꾸기.

### 4-0. ★ 원스톱 마스터 프롬프트 (이것 하나만 써도 됨)

```
너는 경기도의원 이채명 의원실의 의정활동 콘텐츠 비서다.
아래 [원자료]를 바탕으로 다음 7가지를 순서대로, 한 번에 작성해라.
각 결과물은 제목을 붙여 구분하고, 모르는 사실은 지어내지 말고 "[확인 필요]"로 표시해라.

■ 기본 정보
- 의원: 경기도의원 이채명 (안양)
- 활동 종류: [간담회 / 현장방문 / 정책포럼 / 민원상담 / 상임위 질의 중 택1]
- 날짜·장소: [2026.10.18 / ○○동 주민센터]
- 참석자: [예: ○○초 학부모 12명, 안양시 교통과 담당자]
- 사진 목록: [예: 1)간담회 전경 2)발언 장면 3)통학로 현장 4)단체사진]

■ 원자료 (녹취·메모 붙여넣기)
[여기에 녹취록이나 메모를 그대로 붙여 넣기]

■ 작성할 결과물
1) 회의 요약
   - 한 줄 요약 / 참석자 / 주요 발언(발언자 익명 처리: "학부모 A") / 요청사항 / 의원이 약속한 것

2) 분류표 (표로)
   | 구분(민원·정책·조례·예산·후속확인) | 내용 | 담당 기관(도/시/교육청) | 우선순위(상·중·하) | 다음 할 일 | 기한 |

3) 후속 업무 초안
   - 민원이 있으면: 담당 부서에 보낼 "민원 처리 요청서" (현황-문제-요청-회신기한)
   - 정책 방향이 있으면: 1쪽 "정책 메모" (배경-현황-문제점-개선방안-기대효과)
   - 조례 필요성이 있으면: "조례 검토 메모" (관련 현행 법령·조례 [확인 필요] 표시, 제정/개정 방향, 주요 조문 아이디어)

4) 블로그 글 (네이버 블로그)
   - 제목 3안 (주민이 검색할 만한 단어 포함, 30자 내외)
```

## 6. 반드시 지킬 것

> AI가 만든 결과물은 **초안**입니다. 올리기 전 사람이 최종 확인합니다.

**① 사실 확인**
- 법령명·조문·예산액·통계는 AI가 그럴듯하게 지어낼 수 있음 → 국가법령정보센터, 자치법규정보시스템, 도 예산서로 확인.
- "[확인 필요]" 표시가 하나라도 남아 있으면 게시하지 않기.

**② 개인정보·초상권**
- 민원인 이름·주소·연락처·사연의 특정 정보는 블로그·영상에서 빼기 ("주민 A").
- 아이·학생 얼굴은 보호자 동의 없으면 모자이크 또는 뒷모습 사진만.
- 녹음은 참석자에게 사전에 알리고 진행.
- 민원 원문을 외부 AI 서비스에 넣을 때도 이름·연락처는 먼저 지우고 넣기.

**③ 공직선거법 (특히 선거 6개월 전부터)**
- 의정활동 보고는 가능하지만, 시기·방법·표현에 따라 제한될 수 있음.
- "지지해 주십시오", 정당 기호, 상대 비방, 확정되지 않은 공약성 약속 표현 피하기.
- 애매하면 **관할 선거관리위원회에 미리 문의** (정확한 기준은 선관위 안내를 따르세요).

**④ AI 생성물 표시**
- AI로 만든 영상·이미지에는 설명란에 "본 영상은 AI 도구를 활용해 제작했습니다" 같은 문구를 넣는 것을 권장.
- 실존 인물(의원 본인 포함)의 얼굴·목소리를 AI로 합성하지 않기. 의원 얼굴은 **실제 사진**, 목소리는 **본인 녹음**으로.

**⑤ 저작권**
- 배경음악·효과음은 저작권 걱정 없는 무료 음원(유튜브 오디오 보관함 등)만 사용.
- 레퍼런스 영상은 분위기·움직임만 참고, 그대로 베끼지 않기.
